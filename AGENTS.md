# Repository guidelines

## Repository overview

`using-temporary-files` is a small ESM TypeScript package for creating disposable file-system fixtures in tests.
`temporaryFiles()` is the primary explicit-resource-management API, while `usingTemporaryFiles()` is the deprecated callback-based compatibility API.
`src/using-temporary-files.ts` contains the implementation.
`dist/` contains the checked-in JavaScript and type declarations generated by `npm run build`.
`test/using-temporary-files.test.js` covers the package APIs with Node's built-in test runner.
`test/markdown.test.mjs` finds `js unit-test` fences in Markdown files and executes those examples.
`.changeset/` contains release notes, and the GitHub workflows test Node.js 22 and 24 before publishing through Changesets.

## Working agreements

Write Markdown files with one sentence per line to keep diffs clean.
Keep changes focused and preserve unrelated worktree changes.
Commit after each small, coherent batch of changes instead of accumulating unrelated work in one commit.
Inspect the diff and run the narrowest relevant checks before each commit.
Run `npm test` and `npm run lint` for code changes.
Run `npm run test:markdown` after changing a `js unit-test` example.
Run `npm run build` after changing TypeScript and commit the regenerated `dist/` files with the source change.
Add or update a changeset when a change should appear in the next package release.
Do not include unrelated user changes in a commit, and do not push unless the user explicitly asks.
